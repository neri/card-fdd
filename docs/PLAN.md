# card-fdd 実装計画書

M5Stack Cardputer を **USB フロッピードライブ** として動かすファームウェア。
MicroSD に置いたフロッピーイメージを選んで「挿入」すると、PC からは USB フロッピー（Windows では A: ドライブ）として見える。

- 対象機種: M5Stack Cardputer v1.1（ESP32-S3 / StampS3）。Cardputer-Adv にも後から対応できるようにしておく
- 言語・環境: Rust、`no_std`（esp-hal + Embassy）
- ステータス（2026-11-22）: Phase 0〜7 を実装済み。Windows で空のまま接続したときの約 20 秒周期の USB リセットを修正し、実機で再現しないことを確認した（8.4 節）。堅牢化の残作業と未確認の項目は 8.1 節と 9 章のチェックリストを参照。音色の調整は保留。
- 追加（2026-11-26）: SD リーダーモードを実装した（1.3 節、Q6、[SD_READER_PLAN.md](SD_READER_PLAN.md)）

## 1. 要件

### 1.1 必須機能

| ID | 機能 | 内容 |
|----|------|------|
| F1 | USB フロッピー | USB-C で PC（Windows / macOS / Linux）につなぐと、**フロッピードライブとして**認識される |
| F2 | イメージ選択 | MicroSD 内の生イメージ（`.img` / `.ima`）を、挿入するディスクとして選ぶ。サブフォルダもたどれる |
| F3 | 画面表示 | 液晶に現在のステータスとイメージ選択画面（セレクター）を表示する |
| F4 | 書き込み | PC からイメージに書き込める。本体の操作で書き込み禁止（WP）に切り替えられる |
| F5 | 自動挿入 | 起動すると、前回挿入していたイメージが挿入された状態になる（設定で無効にできる） |
| F6 | 単体操作 | USB につながず電池で動かしているときも、イメージを選んでおける（自動消灯は外した） |

### 1.2 任意機能（余裕があれば）

| ID | 機能 | 内容 |
|----|------|------|
| O1 | アクセス音 | 内蔵スピーカーでシーク音、ステップ音、モーター音、ヘッドロード音を鳴らす。音は合成で作る |
| O2 | アクセスランプ | 内蔵 RGB LED（WS2812, G21）をアクセスランプとして光らせる |
| O3 | 実機速度モード | 実機 FDD 並みの遅延をわざと入れる。設定でオンオフでき、既定はオフ |
| O4 | 空イメージ作成 | フォーマット済みの空イメージを本体だけで作る |

### 1.3 将来の課題（今回は作らない）

- Cardputer-Adv への対応（機種に依存する部分は trait で分けておく）
- 1.44MB 以外のフォーマット（720K / 1.2M / 1.25M / 2.88M）
- ヘッダ付きのイメージ形式（.d88 / .fdi / .hdm など）
- ~~SD リーダーモード（SD 全体を USB マスストレージとして PC に見せる）~~ → 実装した（2026-11-26、[SD_READER_PLAN.md](SD_READER_PLAN.md)）
- 録音した PCM や SD 上の WAV を音源に使う
- 日本語ファイル名の表示
- 電池駆動時のディープスリープ

### 1.4 非機能要件

- イメージの切り替え（メディア交換）を PC 側が正しく検出できること
- 書き込み中にイメージを切り替えても、イメージファイルと SD の FAT が壊れないこと
- 起動から USB 認識まで 2 秒程度
- 転送速度の目安: USB Full Speed（12Mbps）の上限近く。1.44MB 全体の読み出しが数秒で終わればよい

## 2. ハードウェア前提

開発と動作確認は **Cardputer v1.1** で行う。ピン番号は実装を始める前に M5 公式ドキュメントと回路図で確認すること。

| 機能 | デバイス | 接続（v1.1） | Adv との違い |
|------|----------|-------------|-------------|
| MCU | ESP32-S3FN8 | – | 240MHz デュアルコア、SRAM 512KB、Flash 8MB、**PSRAM なし** |
| USB | ESP32-S3 内蔵 USB OTG | D- G19 / D+ G20 | Full Speed のみ。USB-Serial-JTAG と PHY を共有する |
| 液晶 | ST7789V2 1.14" 240×135 | SPI: MOSI G35, SCK G36, CS G37, DC G34, RST G33, BL G38 | |
| MicroSD | – | SPI: SCK G40, MISO G39, MOSI G14, CS G12 | 液晶とは別バス。SPI2 と SPI3 に分ける |
| キーボード | 56 キーのマトリクス + 74HC138 | 行選択 G8, G9, G11 / 列入力 G13, G15, G3–G7 | Adv では TCA8418（I2C） |
| スピーカー | NS4168（I2S アンプ） | BCLK G41, LRCK G43, DATA G42 | Adv では ES8311 コーデック（I2C で初期設定が必要） |
| RGB LED | WS2812 | G21 | アクセスランプに使う（O2）。電源は G38 のバックライトと共通 |
| ボタン | BtnG0 | G0 | 起動時に押していると書き込みモード（公式の手順は、電源 OFF で G0 を押しながら USB を挿す） |
| 電池電圧 | ADC | G10 | ステータスに電池残量を表示 |

### 2.1 機種に依存する部分の分け方

Adv に後から対応できるよう、機種ごとに違う部分を trait で抽象化しておく。今回は v1.1 用の実装だけを作る。

```rust
trait Keyboard { async fn next_event(&mut self) -> KeyEvent; }
trait AudioOut { async fn write(&mut self, samples: &[i16]); fn set_volume(&mut self, v: u8); }
trait Battery  { fn level_percent(&mut self) -> Option<u8>; }
```

- `board::v1` に v1.1 用の実装をまとめ、cargo feature（`board-v1` / 将来 `board-adv`）でどちらをビルドするか選ぶ
- 液晶、SD、USB、LED は両機種で共通の想定（Adv に対応するときに確認する）

### 2.2 開発時の注意: USB を MSC に使うとシリアルログが使えない

ESP32-S3 の USB PHY は USB-Serial-JTAG と USB OTG のどちらか一方しか使えない。
OTG に切り替えた後は、USB 経由の `esp-println` も `espflash monitor` も使えない。

- **ログ出力**: Grove ポート（G1/G2）の UART に USB-UART 変換器をつなぐ。あわせて、画面にデバッグ表示を出せるようにしておく
- **書き込み**: G0 を押したままリセットしてダウンロードモードに入る。アプリ側にも「ダウンロードモードで再起動」するキー操作を用意しておくと開発が楽になる
- **初期の開発**: OTG を有効にするまでは USB-Serial-JTAG でログを見る
- **ダウンロードモードのビットが残る**: Ctrl+Alt+D は `RTC_CNTL_OPTION1.FORCE_DOWNLOAD_BOOT` を立てて再起動する。このビットは USB 経由のリセットでもウォッチドッグリセットでも消えず、espflash も消さないので、そのままだと書き込み後もダウンロードモードで起動してしまう。`cargo run` のランナー（`tools/flash.sh`）が、書き込み後に `tools/clear-download-boot.py` でこのビットを消してから起動する
- **起動直後のログ**: `espflash monitor` は接続し直す間に起動直後のログを取りこぼすので、`tools/monitor.py`（RTS でリセットしてそのまま読む）を使う
- **JTAG と OTG の切り替え**（Phase 3 で判明）:
  - PHY を切り替えるだけだと D+ が Low になる時間が短く、ホストは前のデバイスがつながったままだと思い込む（EPROTO になり、新しいデバイスが列挙されない）。切り替える前に、元の側のプルアップを外して 200ms 待つ
  - PHY の選択（RTC_CNTL.USB_CONF）と USB-Serial-JTAG のプルアップ設定は、ソフトウェアリセットでは戻らない。再起動の前に JTAG の状態へ戻さないと、ROM のダウンロードモードが OTG 側で動いたり（espflash ではスタブの転送が失敗して書き込めない）、ホストから見えなくなったりする（`board::system::restore_usb_serial_jtag`）
  - 開発中は USB を「マスストレージ + CDC-ACM」の複合デバイスにする（feature `dev-cdc`、既定では無効なので `--features dev-cdc` を付ける）。`tools/flash.sh` が CDC に `download` を送ってダウンロードモードにしてから書き込むので、`cargo run --features dev-cdc` だけで書き込める
  - 書き込みスクリプトでポートを開くときは、DTR を立てたまま開いてから下げる（pyserial の既定の順だと一瞬「RTS=1, DTR=0」になり、USB-Serial-JTAG がリセットと受け取る）
  - OTG に切り替えたあと、USB-Serial-JTAG 側のプルアップ・プルダウンはすべて外す（切り離しのために入れたプルダウンを残さない）
- **Windows で試すとき**は CDC なし（既定）でビルドし、UFI + CBI と既知の USB フロッピーの VID/PID を使う（3.3 節）。
  次の環境変数はビルド時の既定値を指定する。SD の `CARDFDD.CFG` に `usb_mode` / `usb_vid` / `usb_pid` があれば、項目ごとにファイルの設定が優先される。
  既存の設定ファイルを使う場合は該当する 3 項目も確認し、必要なら編集して本体を再起動する。次に Linux で書き込むときは本体で Ctrl+Alt+D を押す。

  ```
  CARDFDD_USB_MODE=ufi-cbi CARDFDD_USB_VID=0644 CARDFDD_USB_PID=0000 cargo run --release
  ```

## 3. ソフトウェア構成

### 3.1 クレート候補

バージョンは「リリースから 1 週間以上たった最新の安定版」を選ぶ。
ライセンスは未定だが、どちらに決めても困らないよう、依存ライブラリは **MIT / Apache-2.0 互換のものに限る**。

| 用途 | クレート | 備考 |
|------|---------|------|
| HAL | `esp-hal` | `otg_fs` が unstable feature の可能性あり。要確認 |
| 非同期ランタイム | `embassy-executor`, `embassy-time`, `embassy-sync` + esp 用の統合クレート（`esp-rtos` か `esp-hal-embassy`。現行の構成を確認すること） | |
| USB | `embassy-usb` + `esp_hal::otg_fs::asynch::Driver` | MSC クラスは自作する（3.3 節） |
| FAT | `embedded-sdmmc` | FAT16/32。**LFN の読み出しにどこまで対応しているか要確認**。exFAT は非対応 |
| 液晶 | `mipidsi` + `embedded-graphics` | ASCII のフォントだけを使う |
| その他 | `heapless`, `static_cell`, `esp-backtrace`, `esp-println` | `alloc` は原則使わない |

ツールチェーン: Xtensa 用に `espup` で esp ツールチェーンを入れ、書き込みは `espflash` で行う。
プロジェクトの雛形は `esp-generate` で作る。

### 3.2 タスク構成（Embassy）

```
                ┌──────────────┐  ブロック要求    ┌──────────────┐
  PC ⇄ USB ⇄   │  usb_task     │ ───────────────▶│ storage_task │ ⇄ SPI3 ⇄ MicroSD
                │ (CBI/BOT +    │ ◀───────────────│ (FAT + イメージ │
                │  UFI/SCSI)    │  データ / 結果   │  のマッピング)  │
                └──────┬───────┘                  └──────┬───────┘
                       │ アクセスイベント（LBA, R/W）       │ メディア状態
                       │ USB 状態（Configured/Suspended）   │
                       ▼                                 ▼
                ┌──────────────┐   共有状態 AppState   ┌──────────────┐
                │ sound_task   │ ◀──────────────────▶ │  ui_task     │ ⇄ SPI2 ⇄ 液晶
                │ (I2S 合成)    │                       │ (表示 + キー)  │ ⇄ キーマトリクス
                └──────────────┘                       └──────────────┘
```

- **usb_task**: USB の列挙、CBI または Bulk-Only の転送、UFI / SCSI コマンドの解釈、USB 状態の通知
- **storage_task**: イメージファイルを開いたり閉じたりし、LBA をファイル内の位置、さらに SD の物理ブロックへ変換して読み書きする
- **ui_task**: 画面描画（変化があったときだけ部分的に更新）、キースキャン（約 10ms 周期）、セレクター操作
- **sound_task**: アクセスイベントからシークやモーターの音を合成し、I2S へ DMA で流す
- タスク間のやり取りには `embassy-sync` の `Channel` / `Signal` / `Mutex` を使う。最初はシングルコアで動かし、音が途切れるようならコア 1 へ移す

### 3.3 USB マスストレージの実装方針

`embassy-usb` には MSC クラスがない前提で、自前で実装する（規模は小さい）。

PC で「フロッピードライブ」として表示させるため、**UFI 方式（subclass 0x04）を本命**にする。
UFI で使う転送方式は CBI（protocol 0x00/0x01）と Bulk-Only（protocol 0x50）の 2 つがある。
OS がどちらを受け付けるかは、Phase 3 で実機確認して決める。

| 方式 | subclass / protocol | PC からの見え方 | 位置づけ |
|------|---------------------|----------------|---------|
| UFI + CBI | 0x04 / 0x00 or 0x01 | フロッピードライブ（A:） | 本命の候補。本物の USB FDD の多くはこの方式 |
| UFI + BOT | 0x04 / 0x50 | フロッピードライブ（OS 次第） | 受け付ける OS が多ければこちらが簡単 |
| SCSI + BOT | 0x06 / 0x50 | 容量 1.44MB のリムーバブルディスク | 開発の足場（USB スタックの確認用）と、うまくいかない場合の予備 |

`usb_mode` 設定（7 章）で方式を切り替えられるようにしておく。コマンド処理の中身は 3 方式で共通にする。

**Phase 3 の結論（2026-11-21）**: Windows でフロッピーとして使うには、次の 3 つがすべて必要。

1. UFI + CBI（`08/04/00`）であること
2. VID/PID が Windows の usbstor.inf に載っている既知の USB フロッピーのものであること。usbstor.inf は UFI（サブクラス 04）を、クラスの組み合わせとしては受け付けず、CBI のフロッピーは製品ごとの VID/PID（TEAC `0644:0000`、Y-E Data `057B:0000/0001` など）でしか扱わない
3. インターフェースが 1 つだけであること。CDC などと組み合わせた複合デバイスだと、デバイス全体に usbstor が当たって開始に失敗する

Linux はどの方式でも、VID/PID に関係なく使える。

このため、既定は「UFI + CBI、VID/PID は pid.codes のテスト用」とする。Windows でフロッピーとして使う場合は、利用者が設定で既知のフロッピーの VID/PID を選ぶ（他社の ID を名乗ることになるので、既定値にはしない）。開発用 CDC（feature `dev-cdc`）は既定では無効で、Windows で試すときは付けない。

対応する主なコマンド:

| コマンド | 内容 |
|---------|------|
| `INQUIRY` | RMB（リムーバブル）=1 を返す。ベンダー名と製品名は設定値 |
| `TEST UNIT READY` | メディア状態に応じて GOOD / NOT READY / UNIT ATTENTION を返す |
| `REQUEST SENSE` | 直前のエラーの詳細（センスデータ）を返す |
| `READ CAPACITY(10)` | 最終 LBA とブロック長。ブロック長はイメージごとに決まる（3.4 節） |
| `READ FORMAT CAPACITIES` | 現在のメディア容量と、フォーマット可能な容量の一覧（初期は 1.44MB だけ） |
| `READ(10)` / `READ(12)` | |
| `WRITE(10)` / `WRITE(12)` | 書き込み禁止中は DATA PROTECT（07/27/00）を返す |
| `MODE SENSE(6/10)` | WP ビット。UFI では Flexible Disk Page（0x05）も返す |
| `MODE SELECT(10)` | 受け取って無視する |
| `PREVENT ALLOW MEDIUM REMOVAL` | PC がイジェクトを禁止している状態を UI に表示する |
| `START STOP UNIT` | PC 側からのイジェクト要求 |
| `VERIFY` | 常に成功を返す |
| `FORMAT UNIT` | 指定トラックの範囲を 0xF6 で埋める（Windows のフォーマットで使う） |
| `SEND DIAGNOSTIC` / `REZERO` / `SEEK(10)` | 成功を返す。SEEK はシーク音のきっかけにも使う |

**メディア交換のシーケンス**（センスデータは Sense Key/ASC/ASCQ の順）:
1. イジェクト: 未書き込みデータを書き出す → ファイルを閉じる → 以後 `TEST UNIT READY` に NOT READY（02/3A/00 MEDIUM NOT PRESENT）を返す
2. 挿入: ファイルを開く → 最初の 1 回は UNIT ATTENTION（06/28/00 NOT READY TO READY CHANGE）を返す → 以後 GOOD
3. PC が `PREVENT MEDIUM REMOVAL` 中の場合: UI に警告を出し、確認したうえで強制イジェクトさせる

**USB ディスクリプタ**:
- VID/PID の既定値は pid.codes のテスト用（VID 0x1209）。設定ファイル（7 章）で VID / PID / 製造者名 / 製品名を上書きできる
- ディスクリプタは起動時に読み込むので、設定の変更は再起動してから反映される

### 3.4 ストレージ層

- PSRAM がないため、イメージ全体を RAM に載せることはできない。基本は SD に直接アクセスする
- イメージを開くときにクラスタチェーンを調べる
  - **ファイルが連続配置なら**「先頭の物理ブロック + オフセット」だけで直接読み書きする（高速で、FAT 層を通らない）
  - **断片化していれば**クラスタ表を `heapless::Vec` に持つ。1.44MB で 4KB クラスタなら約 360 エントリ
- 書き込みは SD のブロック単位（512B）で直接行い（ライトスルー）、ファイルサイズは変えない。FAT のメタデータ（更新日時など）はイジェクトするときだけ更新する
- 読み出しキャッシュとして、1 トラック分（1.44MB なら 18 セクタ × 512B = 9KB）を RAM に持つ。シーク音の判定にもトラック単位の情報を使う
- **ブロック長は可変**にしておく。`Geometry { cylinders, heads, sectors, bytes_per_sector }` からすべてを計算し、512 という数をコードに直接書かない。1024 バイトセクタ（PC-98 の 1.25MB）を後から足せるようにするため
- 対応する形式は生イメージ（`.img` / `.ima`）だけ。ジオメトリはファイルサイズから決める

| サイズ | 種類 | C/H/S | セクタ長 | 初期対応 |
|------|------|-------|---------|:-------:|
| 1,474,560 | 1.44M（2HD） | 80/2/18 | 512 | ✅ |
| 737,280 | 720K（2DD） | 80/2/9 | 512 | 将来 |
| 1,228,800 | 1.2M（2HC） | 80/2/15 | 512 | 将来 |
| 1,261,568 | 1.25M（PC-98 2HD） | 77/2/8 | 1024 | 将来 |
| 2,949,120 | 2.88M（ED） | 80/2/36 | 512 | 将来 |

初期対応でないサイズのファイルは、セレクターに薄い色で「非対応」と表示し、選べないようにする。

### 3.5 UI

```
┌────────────────────────────────────────┐
│ card-fdd        USB:● HOST     BAT 87% │
│────────────────────────────────────────│
│ DISK: Game Disk 1 (Boot).img           │
│       1.44MB  2HD  80/2/18   [WP]      │
│                                        │
│  TRK 42  HEAD 1  SEC 07   ■ READ       │
```

**セレクター画面**
```
┌────────────────────────────────────────┐
│ /FLOPPY/GAMES/               12 files  │
│────────────────────────────────────────│
│   <DIR> ..                             │
│   <DIR> Utilities                      │

```

- ファイル名は LFN（長いファイル名）で表示する。ASCII 以外の文字は `?` に置き換える。画面に収まらない名前は、選択中の行だけ横にスクロールする
- サブフォルダをたどれる。起点のフォルダは `image_dir` 設定（既定 `/FLOPPY`）
- Cardputer のキー配置に合わせ、`;` / `.` を上下、`,` / `/` を左右として使う（Fn との組み合わせも検討）
- 頭文字の入力で目的のファイルにジャンプする
- 画面全体を毎回描き直さず、変化した部分だけ描画する（SPI の帯域節約と、ちらつき防止）

### 3.6 サウンド（任意: O1, O3）

- アクセスイベント（LBA と R/W）から目的のトラックを計算し、現在のトラックとの差分でステップ回数を決める
  - ステップ音: 約 3ms 間隔でクリック音を差分の回数だけ鳴らす
  - シーク距離が長い場合は、連続したステップ音が「ジー」という音になる
- 音の種類: モーターの回転音（ループ）、ヘッドロード音、ステップ音、イジェクト音
- **音源は合成で作る**（ノイズ + 減衰エンベロープ。Flash はほとんど使わない）。後で PCM に差し替えられるよう、音源を `trait SoundSource` で抽象化しておく
- I2S は 16bit / 16kHz モノラル。DMA のダブルバッファで流す
- 音量は 0〜3 段階とミュートを、キーで切り替える
- **実機速度モード（O3）**: usb_task がコマンドに応答する前に、実機相当の待ち時間を入れる（シーク約 3ms/トラック、回転待ち平均約 100ms、転送 500kbps 相当）。既定はオフ

### 3.7 電源と USB 接続状態

- **USB 状態の判定**: embassy-usb の状態通知を使う。Configured になれば「PC に認識された」、Suspended / Disabled になれば「未接続」と表示する
- **ケーブルの抜き差しそのものは検出しない**。v1.1 では VBUS が GPIO につながっていない想定のため（回路図で要確認）。「ケーブルを抜いた」「PC がスリープした」「充電器だけにつないだ」は、どれも「未接続」になる
- **電池で動いているとき**も、イメージの選択、書き込み禁止の切り替え、設定変更はすべてできる。選んだイメージは、USB でつなぐとすぐ使える
- ~~**自動消灯**~~: 実装したが、使い勝手が悪いため外した（2026-11-22、8.5 節）
- 電池残量は G10 の ADC 電圧から推定して、ステータス画面に表示する
- ディープスリープは将来の課題とする

## 6. 主なリスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| esp-hal の USB OTG + embassy-usb が不安定、または unstable API | USB 機能の土台が揺らぐ | Phase 3 で最初に確認する。駄目なら `usb-device` + `synopsys-usb-otg` 系に切り替える |
| UFI 方式を受け付けない OS がある | その OS では「フロッピー」として見えない | 方式を設定で切り替えられるようにし、駄目な OS では SCSI+BOT を使う |
| embassy-usb で CBI（ADSC 制御リクエストと割り込みエンドポイント）が書きにくい | UFI+CBI の実装コストが増える | Phase 3 で試作する。必要なら、制御リクエストのハンドラを自作する |
| 書き込み中のイメージ切り替えで破損する | データ消失 | ライトスルーにする。PREVENT 中は警告を出す。イジェクト前にアクセスが終わるのを待つ |
| embedded-sdmmc の LFN 対応が不十分 | 長いファイル名が表示されない | Phase 2 で確認する。足りなければ、LFN のディレクトリエントリの読み出しだけ自作する |
| RAM 不足（512KB、PSRAM なし） | キャッシュや画面バッファを持てない | 画面はフルフレームバッファを持たず部分描画にする。キャッシュは 1 トラック分に抑える |
| SD と USB の速度差 | 転送が遅い | 連続配置への直接アクセス、マルチブロック読み出し、SPI クロックを上げる（最大 40MHz） |
| 開発中にログが見えない | デバッグが困難 | 2.2 節の UART ログと画面のデバッグ表示 |

## 7. 設定と永続化

SD のルートに `CARDFDD.CFG`（key=value 形式のテキスト、`#` から行末はコメント）を置く。ファイルがなければ既定値で動き、挿入・取り出し・書き込み禁止の切り替えのたびに保存する（`src/config.rs`）。

```
image_dir=/FLOPPY            # イメージを置くフォルダ
last_image=v1:/FLOPPY/TEST.IMG  # 前回のイメージ（自動で書き換わる。取り出すと空になる）
auto_mount=1                 # 起動時に前回のイメージを挿入する
write_protect=0              # 書き込み禁止スイッチ
usb_mode=ufi-cbi             # ufi-cbi | ufi-bot | scsi（usb_* は再起動後に反映）
usb_vid=0x1209               # Windows でフロッピーとして使うには既知の USB フロッピーの値
usb_pid=0x0001
usb_manufacturer=card-fdd
usb_product=USB Floppy
```

設定ファイルにない項目の USB の既定値は、ビルド時の環境変数（`CARDFDD_USB_MODE` / `CARDFDD_USB_VID` / `CARDFDD_USB_PID`）でも変えられる。

`last_image` は `v1:` で始まり、スペース・`#`・`%`・制御文字を `%XX` にしたパスで保存する（LFN をそのまま UTF-8 で書く）。`v1:` のない以前の形式（表示名のパス）も読める。詳細は DESIGN.md 8 章。設定ファイルは行ごとに UTF-8 として読み、読めない行だけを無視する。

Phase 7 で次の 2 つを追加した。

```
volume=2                     # アクセス音の音量（0 = 消音 .. 3）。s キーで切り替え
speed_emulation=0            # 実機速度モード（1/0）。r キーで切り替え
```

Flash の NVS は使わない。SD を差し替えたときに設定ごと移せるほうが便利なため。

### 8.1 実装中に確認すること

- [x] v1.1 の回路図: VBUS 検出線の有無と、ピン番号の確認（2026-11-22、M5Stack 公式の回路図 PDF で確認）
  - 回路図: [Cardputer V1.1](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1127/Sch_M5Cardputer.pdf)、[ベース基板](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1127/M5Cardputer_Base.pdf)、[Stamp-S3A](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1150/Sch_StampS3_v0.3.3.pdf)（[公式ドキュメント](https://docs.m5stack.com/en/core/Cardputer_v1.1)）
  - **VBUS を検出する GPIO はない**: USB-C の VBUS はヒューズを通って `VIN_5V`（本体側 `+5VIN`）になり、充電 IC（TP4057）と電源の切り替えに行くだけ。充電 IC の状態ピン（CHRG / STDBY）も GPIO にはつながっていない。USB の接続は USB スタックの状態通知で判断する（3.7 節のとおり）
  - ピン番号は 2 章の表どおり。USB D+ / D- は GPIO20 / GPIO19。電池電圧は 100kΩ + 100kΩ の分圧で G10
  - G38 は電源スイッチ（AW35122）の EN で、その出力が **液晶のバックライトと RGB LED の両方の電源** になっている。バックライトを消したり PWM で絞ったりすると LED も消える（公式ドキュメントにも「バックライトが 100% 未満だと RGB に正しく電源が来ない」とある）
  - スピーカーアンプ（NS4168）の CTRL は電源側につながっていて常に有効。G43 はマイクのクロックとスピーカーの LRCLK を兼ねる（マイクは使っていない）
- [x] esp-hal の `otg_fs` の安定性と、embassy 統合クレートの現行構成（esp-hal 1.2 + esp-rtos 0.4 + embassy-usb 0.6 で動作。サスペンドの扱いなど細部は 8.4 節）
- [x] embedded-sdmmc の LFN 対応状況（0.10 の `iterate_dir_lfn` で読める）
- [x] 各 OS が UFI を CBI と BOT のどちらで受け付けるか（Phase 3）
  - Linux: UFI+CBI、UFI+BOT、SCSI+BOT のどれも認識され、読み書きできる（2026-11-21 確認。Linux は UFI も普通のリムーバブルディスクとして扱う）
  - Windows: UFI+BOT（`Prot_50`）にも、テスト用 VID/PID の UFI+CBI（`Prot_00`）にも標準ドライバが当たらない。UFI+CBI + TEAC の VID/PID（`0644:0000`）+ 単一インターフェースで動いた。A: のフロッピーとして認識され、ファイルのコピーとフォーマットもできた（2026-11-21 確認）
  - macOS: 未確認
- [ ] pid.codes のテスト用 PID の値と、使うときの条件

### 8.6 Phase 7 の結果（2026-11-22）

- 音の合成（`src/sound/synth.rs`）: 録音は使わず、共振器で作る。調整用の定数はファイルの先頭にまとめた
  - ステップ音: 450Hz の短い響きと 100Hz の胴鳴りを重ねた低い「コッ」。シークでは 3ms 間隔で連続する
  - モーター音: うなりは鳴らさず、ディスクがこすれる音（180Hz 付近）をごく小さく鳴らす。最後のアクセスから 2 秒で止まる
  - 挿入 / 取り出し: 機械音の再現はやめ、電子音（挿入は上がる 2 音、取り出しは下がる 2 音）にした
  - 経緯: 最初の音は HDD のよう（高い「チッ」とモーターのうなり）で、「サー」「ジー」というノイズも目立ったため、聞いてもらいながら作り直した
- 音の DMA は、補充が間に合わずに空になると止まる。バッファを 256ms 分にし、止まったら作り直して再開する（起動直後に SD の処理で止まり、以降無音になっていた）
- 出力（`src/board/v1/audio.rs`）: NS4168 に I2S（16kHz・16bit ステレオ）を DMA のストリームバッファで流し続ける
- USB の読み書きでは、セクタごとにシリンダを求め、変わったとき（と 100ms ごと）に音へ知らせる（`usb::transfer::mechanics`）
- 実機速度モード（O3）: セクタごとに 1 回転 / 1 トラックのセクタ数、シークで 3ms × トラック数 + 静定 15ms、モーターが止まっていれば立ち上がり 300ms を待つ。300KB の読み出しが 0.7 秒 → 7.5 秒（約 40KB/s）になることを確認
- キー: s で音量（0〜3）、r で実機速度モード。設定ファイルの `volume` / `speed_emulation` に保存する
- 音色の確認と調整は、実機で聞いて行う

### 8.5 Phase 6 の結果（2026-11-22）

- 画面と操作を `src/app.rs` にまとめ、`src/bin/main.rs` は初期化とタスクの起動だけにした
- ステータス画面（`src/ui/status.rs`）: ディスク名、フォーマット、[WP]、USB の状態（PC / -- / zz）、電池、アクセス位置（トラック / ヘッド / セクタ、読み書き）とトラックのバー

- 画面の見た目とキー操作は、実機の画面での確認が必要

### 8.3 Phase 5 の結果（2026-11-21）

- ホストとのやり取りの状態（取り出し禁止、イジェクト要求、転送中）を `usb::HOST` で UI と共有する

- Windows で、本体から取り出したあとに A: を開くとすぐに媒体の挿入を求められることを確認した（2026-11-22）。イメージの連続入れ替えと、SD 上のイメージに対する FORMAT UNIT による通常フォーマットは未確認。

### 8.4 Windows での不具合の調査（2026-11-21〜22）

SD 上のイメージを使うようになってから（Phase 4 以降）、Windows で問題が出た。本体の画面に USB の診断パネル（`u` キー）を作り、Windows でのやり取りを記録して調べた。

- `REQUEST SENSE` の完了割り込みが Windows で未読のまま残り、次のコマンドの完了通知を送れないことがあった。新しい ADSC を受けたときに、前の完了割り込みと Bulk IN の残りを破棄するようにした（`usb::discard_pending_in`）。
- 起動時の自動挿入で、列挙直後のコマンドに UNIT ATTENTION を返すと約 20 秒後に一度リセットされた。バスリセット後の最初のコマンドで媒体の世代番号を合わせるようにし、ディスク挿入状態で接続したときのリセットを解消した（`HostState::new_connection`）。
- 空のまま接続すると `READ CAPACITY` の失敗と `REQUEST SENSE` のあとに約 20 秒周期で USB リセットが起きた。認識後に本体で取り出した場合は、空の状態で A: を開いたときにもリセットと Windows のタイムアウトが起きた。どちらの場合も、`REQUEST SENSE` の Bulk IN の送信待ちが解消したあとに、Interrupt IN が残る例を観測した。
- `TEST UNIT READY`、`READ CAPACITY`、`MODE SENSE(10)`、`READ(10)` が媒体交換または媒体なしで失敗する場合、ADSC のステータス段で STALL を返すようにした。取り出し後のアクセスでは `TEST UNIT READY` の変更で Windows がすぐに媒体の挿入を求めるようになった。残り 3 コマンドにも適用し、空接続のリセットを解消した。詳細は [DESIGN.md](DESIGN.md) の 5.4 節を参照。
- 最終版の Windows 実機確認（2026-11-22）では、ディスク挿入状態で A: から読み出せた。空接続では構成完了から 30.7 秒後も `rst1 cfg1` で、再構成は起きなかった。媒体なしの失敗 24 件をすべて ADSC で STALL として通知し、`REQUEST SENSE` 24 件の Bulk IN と Interrupt IN の両方で送信待ちの解消を観測した（`S24`、`sense blk:24/24 int:24/24`）。
- 診断パネルの各項目は `src/app.rs` の `usb_stats_lines` のコメントを参照。開発用 CDC の `stats` には、コマンド間隔やサスペンドなどの詳細も出る。

### 8.2 Phase 4 の結果と残した課題（2026-11-21）

- SD 上のイメージを USB に公開できた。挿入時に FAT からクラスタチェーンをたどって連続範囲の一覧にし、以降は SD の物理ブロックに直接読み書きする（`storage::fat`, `storage::image`）
- Linux で確認: 既存イメージの読み出し（書き込み禁止で挿入）、試験用イメージへの 1.2MB の書き込みと、取り出し → 再挿入後の照合
- 速度: 読み出し約 440KB/s、書き込み約 120KB/s（1 セクタずつ SD に書いているため）
- 残した課題:
  - [ ] 書き込みの高速化（複数セクタをまとめて SD のマルチブロック書き込みにする）→ Phase 8。仕組み（`Disk::write_blocks` と、まとめて受け取るデータフェーズ）は SD リーダーモードで入れた（SD_READER_PLAN.md 14.8 節）。フロッピーの `ImageDisk` で連続範囲ごとに使えば速くなる
  - [x] ~~取り出し時にイメージファイルの更新日時を書き換える~~ → 見送り。Cardputer には RTC がなく、固定の日付で上書きするとかえって情報が失われるため。ディレクトリのブロックを直接書き換えると embedded-sdmmc のキャッシュと食い違う危険もある
  - [x] embedded-sdmmc のブロックキャッシュと、USB からの直接書き込みの整合 → 情報表示を生ブロックの読み出しに変えて解消（Phase 5）
  - [x] 空イメージ作成（O4）を UI に載せ、分割して書くようにした（Phase 6）

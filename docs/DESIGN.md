# card-fdd 設計書

M5Stack Cardputer v1.1 を USB フロッピードライブとして動かすファームウェアの、現時点（2026-11-22、Phase 0〜7 実装済み）の仕様と設計をまとめる。
要件・決定事項・開発の経緯は [PLAN.md](PLAN.md) を参照。この文書は「今の実装がどうなっているか」を記す。

---

## 1. 概要

| 項目 | 内容 |
|------|------|
| 対象機種 | M5Stack Cardputer v1.1（ESP32-S3FN8 / Stamp-S3A、PSRAM なし、Flash 8MB） |
| 言語・環境 | Rust（`no_std`）、esp-hal 1.2 + esp-rtos 0.4（Embassy）、embassy-usb 0.6、embedded-sdmmc 0.10 |
| USB | Full Speed、マスストレージ（UFI + CBI が既定）。開発時は CDC-ACM との複合デバイス |
| 媒体 | MicroSD（FAT16 / FAT32）上の 1.44MB 生イメージ（`.img` / `.ima`） |
| 画面 | ST7789V2 240×135。ステータス画面とセレクター |
| 音 | NS4168（I2S）でアクセス音を合成して鳴らす |

### 1.1 できること

- USB で PC につなぐと、フロッピードライブとして認識される（Windows は既知の USB フロッピーの VID/PID が必要。5 章）
- SD 上のイメージを選んで「挿入」すると、PC から読み書きできる。取り出し、書き込み禁止、イメージの入れ替えに対応
- 起動時に前回のイメージを自動で挿入する
- 本体だけで、フォーマット済みの空の 1.44MB イメージを作れる
- アクセス音（ステップ音、ディスクがこすれる音、挿入・取り出しの電子音）と、実機並みの速度に落とすモード
- 設定は SD のルートの `CARDFDD.CFG` に保存する

### 1.2 対応していないこと

- 1.44MB 以外のフォーマット（720K / 1.2M / 1.25M / 2.88M は判定のみで挿入できない）
- ヘッダ付きのイメージ形式（.d88 / .fdi / .hdm など）、exFAT の SD、日本語ファイル名の表示
- SD リーダーモード、Cardputer-Adv、自動消灯（実装したが外した）

## 2. ハードウェア

ピンは M5Stack 公式の回路図（PLAN.md 8.1 節にリンク）で確認済み。

| 機能 | デバイス | ピン | 使い方 |
|------|----------|------|--------|
| USB | ESP32-S3 内蔵 USB OTG | D- G19 / D+ G20 | マスストレージ（+ 開発用 CDC） |
| 液晶 | ST7789V2 | SPI2: MOSI G35, SCK G36, CS G37, DC G34, RST G33 / BL G38 | 40MHz、横向き |
| MicroSD | – | SPI3: SCK G40, MISO G39, MOSI G14, CS G12 | 初期化 400kHz → 20MHz |
| キーボード | 4×14 マトリクス + 74HC138 | 行選択 G8, G9, G11 / 列入力 G13, G15, G3〜G7 | 5ms 周期スキャン |
| スピーカー | NS4168 | BCLK G41, LRCK G43, DATA G42 | I2S0 + DMA_CH0 |
| RGB LED | WS2812（SK6812） | G21 | RMT。アクセスランプ |
| 電池電圧 | ADC1 | G10（1/2 分圧） | 5 秒ごとに読む |
| ログ | UART1 | TX G2（Grove） | 115200bps |
| ボタン | BtnG0 | G0 | 電源 OFF で押しながら USB を挿すとダウンロードモード |

ハードウェア上の制約:

- **VBUS を検出する GPIO はない**。USB の接続状態は USB スタックの通知（設定済みか、サスペンド中か）で判断する。充電の状態も読めない
- **G38 は液晶のバックライトと RGB LED の電源を兼ねる**（電源スイッチ IC の EN）。G38 を Low にすると LED も消える。今は常に High
- NS4168 の CTRL は電源側につながっていて常に有効。G43 はマイクのクロックと共用（マイクは使わない）

### 3.2 タスク

すべて同じ executor（シングルコア）で動く。

| タスク | 役割 |
|--------|------|
| メイン（`main`） | 初期化のあと、キー入力・開発用コマンドの処理と `App::tick`（20ms ごと、空イメージ作成中は 5ms ごと）、電池電圧の読み取り（5 秒ごと） |
| `keyboard_task` | キーマトリクスをスキャンし、`KEY_EVENTS` チャネルに送る |
| `usb_device_task` | embassy-usb の `UsbDevice::run`（列挙、制御転送） |
| `msc_task` | マスストレージ（CBI または BOT）のコマンド処理 |
| `sound_task` | 音の合成と I2S への出力 |
| `cdc_task` | 開発用 CDC（feature `dev-cdc` のときだけ） |

### 3.3 共有資源

| 資源 | 型 | 使う側 |
|------|----|--------|
| SD カード | `&'static RefCell<Browser<SdCard>>`（`SharedSd`） | UI（一覧、設定ファイル、空イメージ）と USB（ImageDisk 経由で生ブロック） |
| 挿入中のイメージ | `&'static RefCell<ImageDisk<SharedSd>>` | UI（挿入・取り出し・書き込み禁止）と USB（`SharedDisk` 経由で読み書き） |
| ホストとの状態 | `usb::HOST: HostState`（アトミック） | USB が書き、UI が読む（取り出し禁止、イジェクト要求、転送中、接続状態、診断） |
| アクセスの通知 | `usb::ACTIVITY: Signal` | USB → UI（LED、アクセス位置の表示） |
| 音のイベント | `sound::post` / `take_event`（チャネル） | USB・UI → 音 |

`RefCell` で足りる理由: すべてのタスクが同じ executor で動き、SD やイメージを借用している間に await しないので、借用が重なることはない。

媒体の切り替えは、USB のデータフェーズ（`HOST.busy`）の外でだけ行う。転送中に挿入・取り出しを指示されたら `App::pending_media_change` に記録し、転送が終わってから `App::poll_drive` で実行する。SD エラーとホストからの取り出し要求も転送が終わってから処理し、保留中の挿入より優先する。転送中はカードの再初期化（`App::mount_card`）も行わない。

### 3.4 起動の順番

1. ロガー（UART1）、タイマー、esp-rtos
2. 液晶、RGB LED、電池の ADC、キーボード（`keyboard_task` を起動）、音（`sound_task` を起動）
3. SD を初期化し、`App::mount_card` で設定ファイルを読み、イメージフォルダを開く
4. 設定の内容（方式、VID/PID、製品名）で USB を組み立てて起動する。ここから USB-Serial-JTAG は使えなくなる
5. `App::auto_insert` で前回のイメージを挿入する
6. メインループ

## 4. ストレージ

### 4.1 フォルダの一覧（`storage::browser`）

- embedded-sdmmc の `VolumeManager` で MBR の第 1 パーティション（ボリューム 0）を開く。このパーティションは FAT16 または FAT32 でフォーマットする
- `iterate_dir_lfn` で長いファイル名を読む。ASCII 以外の文字は `?` に置き換える
- 表示するのはフォルダと `.IMG` / `.IMA`（8.3 形式の拡張子で判定）。隠し属性、システム属性、ボリュームラベル、`.` で始まる名前は表示しない
- 並び順は `..` → フォルダ → ファイル、それぞれ名前順（大文字小文字を区別しない）
- 上限: 1 フォルダ 128 項目、表示名 64 バイト、フォルダの深さ 8
- パスは 8.3 形式の名前で保持し、開くたびにルートからたどる（同時に開くディレクトリは 2 つまで）

### 4.2 イメージへのアクセス（`storage::fat`, `storage::image`）

挿入するとき:

1. 一覧の項目が持つディレクトリエントリの位置（ブロック番号とオフセット）から、32 バイトのエントリを生ブロックで読み、開始クラスタを得る
2. ブロック 0 の MBR から第 1 パーティションを求め、その BPB から FAT のレイアウトを求める（FAT16 / FAT32 のみ。パーティションのないカードは embedded-sdmmc と同じく非対応）
3. FAT をたどってクラスタチェーンを「物理的に連続した範囲」の一覧にする（最大 64 個。超えると挿入しない）。チェーンが途中で終わる、範囲外を指す、同じクラスタに戻る場合は壊れているとみなして挿入しない

読み書き:

- イメージのセクタ番号 → ファイル内のブロック番号 → 連続範囲の一覧で SD の物理ブロック、と変換し、embedded-sdmmc を通さずに 1 ブロックずつ直接読み書きする（ライトスルー）
- ファイルサイズは変えないので、FAT もディレクトリエントリも書き換えない。更新日時も書き換えない（RTC がないため）
- 書き込み禁止は「ドライブのスイッチ（設定で保存）」と「ファイルの読み取り専用属性」の論理和
- 情報表示（`i`）で読むイメージの先頭も生ブロックで読む（embedded-sdmmc のキャッシュと食い違わないように）

### 4.3 フォーマットの判定（`storage::geometry`）

| サイズ | 種類 | C/H/S | セクタ長 | 挿入 |
|--------|------|-------|---------|:----:|
| 1,474,560 | 1.44M 2HD | 80/2/18 | 512 | ○ |
| 368,640 | 360K 2D | 40/2/9 | 512 | – |
| 737,280 | 720K 2DD | 80/2/9 | 512 | – |
| 1,228,800 | 1.2M 2HC | 80/2/15 | 512 | – |
| 1,261,568 | 1.25M PC-98 | 77/2/8 | 1024 | – |
| 2,949,120 | 2.88M ED | 80/2/36 | 512 | – |

セクタ長は可変で扱い、512 を前提にしていない（非対応のフォーマットを後から足すため）。一覧にないサイズは「?」と表示する。

### 4.4 空イメージの作成

- セレクターの現在のフォルダに `NEW001.IMG`〜`NEW999.IMG` のうち空いている名前で作る
- 中身は `ramdisk::blank_sector` が生成するフォーマット済みの空の FAT12（OEM 名 `CARDFDD`、ボリュームラベル `CARDFDD`）
- `App::tick` ごとに 8 ブロック（4KB）ずつ embedded-sdmmc で書く。USB の転送中と、最後の USB アクセスから 200ms の間は休む（USB を止めないため）

### 4.5 ディスクの抽象化

`storage::Disk` trait（`geometry` / `write_protected` / `media_generation` / `read` / `write`）を USB 側が使う。
`media_generation` は挿入・取り出し・書き込み禁止の切り替え（挿入中）のたびに変わり、USB 側はこれでメディア交換を知る。
`SharedDisk` は `RefCell` に入った Disk を呼び出しのたびに借用するラッパー。

## 5. USB

### 5.1 方式（`usb::UsbMode`）

| 方式（設定値） | Interface（class/subclass/protocol） | エンドポイント | 備考 |
|----------------|------------------------------------|----------------|------|
| `ufi-cbi`（既定） | 08 / 04 / 00 | Bulk OUT、Bulk IN、Interrupt IN（2 バイト、1ms） | 本物の USB フロッピーと同じ |
| `ufi-bot` | 08 / 04 / 50 | Bulk OUT、Bulk IN | Windows では標準ドライバが当たらない |
| `scsi` | 08 / 06 / 50 | Bulk OUT、Bulk IN | 普通のリムーバブルディスクとして見える |

**Windows でフロッピー（A:）として使う条件**（Phase 3 で判明）: UFI + CBI であること、VID/PID が Windows の usbstor.inf に載っている既知の USB フロッピーのもの（例: TEAC `0644:0000`）であること、インターフェースが 1 つだけであること（CDC 付きだと開始に失敗する）。Linux はどの方式でも使える。

ディスクリプタ: 最大消費電流 100mA、EP0 は 64 バイト（その他は embassy-usb の既定値）。VID/PID・製造者名・製品名は設定ファイルで変えられる（既定は pid.codes のテスト用 `1209:0001`、`card-fdd` / `USB Floppy`）。シリアル番号は `CARDFDD0001`。開発用 CDC 付きのときは IAD を使う複合デバイス（device class EF/02/01）。

### 5.2 コマンド処理（`usb::command::Processor`）

| オペコード | コマンド | 応答 |
|-----------|---------|------|
| 00 | TEST UNIT READY | 媒体があれば成功、なければ NOT READY |
| 01 / 2B / 2F | REZERO / SEEK(10) / VERIFY(10) | 媒体があれば成功 |
| 03 | REQUEST SENSE | センスデータ 18 バイト（固定形式）。返したらセンスを消す |
| 04 | FORMAT UNIT（UFI のみ） | パラメータリストを受け取り、指定トラック（または全体）を 0xF6 で埋める |
| 08 / 0A | READ(6) / WRITE(6)（SCSI のみ） | |
| 12 | INQUIRY | 36 バイト。リムーバブル。ベンダー `CARDFDD`、製品 `USB Floppy`、版 `0.1` |
| 15 / 55 | MODE SELECT(6/10) | 受け取って無視する |
| 1A / 5A | MODE SENSE(6/10) | WP ビット。UFI では媒体種別（1.44M = 0x94）と Flexible Disk Page（0x05） |
| 1B | START STOP UNIT | LoEj かつ Start=0 ならイジェクト要求として UI に伝える |
| 1D / 35 | SEND DIAGNOSTIC / SYNCHRONIZE CACHE | 成功 |
| 1E | PREVENT ALLOW MEDIUM REMOVAL | 取り出し禁止の状態を UI に伝える |
| 23 | READ FORMAT CAPACITIES | 現在の容量（フォーマット済み）＋ UFI ではフォーマット可能な容量。媒体がなければ「媒体なし」の記述子 |
| 25 | READ CAPACITY(10) | 最終 LBA とブロック長 |
| 28 / A8 | READ(10/12) | |
| 2A / AA | WRITE(10/12) | 書き込み禁止なら DATA PROTECT |
| その他 | – | ILLEGAL REQUEST（05/20/00） |

主なセンスデータ（キー/ASC/ASCQ）: 媒体なし 02/3A/00、読み出しエラー 03/11/00、書き込みエラー 03/0C/00、LBA 範囲外 05/21/00、メディア交換 06/28/00、書き込み禁止 07/27/00、データフェーズエラー 0B/4B/00。

**メディア交換**: コマンドを受けるたびに `Disk::media_generation` を見て、変わっていれば UNIT ATTENTION（06/28/00）を立てる。INQUIRY と REQUEST SENSE 以外のコマンドで一度だけ返す。媒体が入れ替わったら取り出し禁止の状態も解除する。USB のバスリセットでも、取り出し禁止とホストからの取り出し要求を解除する。USB のバスリセット後の最初のコマンドではそのときの世代番号を基準にするため、接続前から入っている媒体で UNIT ATTENTION は発生しない。

### 5.3 データフェーズ（`usb::transfer::DataPipe`）

- 処理器が返す `DataPhase`（なし / In / Out / Read / Write）に従って、Bulk で転送する。セクタ単位で SD を読み書きしながら 64 バイトのパケットに分けて送受信する
- ホストが想定する転送量（BOT は CBW、CBI はコマンドから計算した `expected_transfer`）より少なく送ったときは、短いパケット（必要なら長さ 0）で終わりを示す。ホストが送ってくる量が多いときは読み捨てる
- Out / Write でホストから届くデータがコマンドに必要な量より少ないとき（短いパケットで途中で終わった、ホストの想定転送量が足りない、転送方向が In）は、そのコマンドを失敗にしてデータフェーズエラー（0B/4B/00）を返す。書き込みは受け取れたセクタまで行う。短いパケットでデータフェーズが終わったら、それ以上は読み捨てない（次の CBW を取り込まないため）
- データフェーズの間は `HOST.busy` を立てる（UI はこの間に取り出さない）
- セクタごとにシリンダを求め、変わったとき（と 100ms ごと）に音のイベントを送る。実機速度モードなら機械的な時間だけ待つ（7.3 節）

### 5.4 CBI（`usb::cbi`）

1. ホストは制御転送のクラスリクエスト ADSC（bRequest 0x00、wIndex = インターフェース）で 12 バイトのコマンドを送る。`CbiControl` が受け取り、容量 1 のチャネルで MSC タスクに渡す。チャネルが満杯の場合は STALL を返す。
2. MSC タスクは新しいコマンドを受けたら、読まれずに残っている前の完了割り込みと Bulk IN データを捨てる。`usb::discard_pending_in` で対象のエンドポイントを NAK にして無効化し、送信 FIFO をフラッシュする。
3. `TEST UNIT READY`、`READ CAPACITY`、`MODE SENSE(10)`、`READ(10)` では、ADSC のステータス段を返す前に MSC タスクがコマンドを判定する。媒体交換（06/28/00）または媒体なし（02/3A/00）で失敗した場合は ADSC のステータス段で STALL を返し、このコマンドの Bulk 転送と完了割り込みを省く。センスデータは後続の `REQUEST SENSE` で取得できる。 [USB-IF CBI 仕様 §2.3.2.1、§2.4.3.1.1](https://www.usb.org/sites/default/files/usb_msc_cbi_1.1.pdf)
4. ADSC を受理したコマンドは必要に応じてデータを転送し、Interrupt IN で完了状態を返す。UFI では成功が 00 00、失敗がセンスの ASC / ASCQ。コマンドブロックリセット（1D 04 FF…）では処理器をリセットし、完了状態は返さない。
5. USB のバスリセットが起きたら、保留中の ADSC とチャネルに残ったコマンドを破棄する。

### 5.5 BOT（`usb::bot`）

CBW（31 バイト、署名 USBC）を受け、データフェーズのあと CSW（13 バイト、署名 USBS、残り長さ、状態）を返す。クラスリクエストは Get Max LUN（0 を返す）と Mass Storage Reset（センスを消す）。

### 5.6 JTAG と OTG の切り替え（`usb::build`, `board::system`）

- 起動時: USB-Serial-JTAG の D+ プルアップを外して 200ms 待ち、ホストに切断を見せてから OTG を初期化する。初期化後は JTAG 側のプルアップ・プルダウンをすべて外す
- 再起動の前（通常の再起動、ダウンロードモードへの再起動）: OTG 側のプルアップを外して 200ms 待ち、PHY の選択（RTC）を JTAG に戻し、JTAG のプルアップの上書きを解除する。PHY の選択とプルアップの設定はソフトウェアリセットでは戻らないため
- ダウンロードモードへの再起動は `RTC_CNTL_OPTION1.FORCE_DOWNLOAD_BOOT` を立ててソフトウェアリセットする。このビットはリセットで消えないので、書き込み後に `tools/clear-download-boot.py` で消す

### 5.7 開発用 CDC-ACM（feature `dev-cdc`、既定では無効）

- ログを送る。ポートが閉じている間（DTR が落ちている間）は送らず、送信が 1 秒終わらなければ接続待ちからやり直す
- 1 行のコマンドを受ける。`download`（ダウンロードモードで再起動）、`reboot` は CDC タスクが処理し、それ以外は UI に渡す
- UI が処理するコマンド: `ls`、`insert <名前>`、`eject`、`wp on|off`、`newimg`、`stats`（USB の診断）、`snd`（音の状態）、`cfg`（設定の表示）、`key tab|enter|esc|<1 文字>`（キー入力の代わり）
- ホストの端末がログを送り返してくることがあるので、`[` で始まる行は無視し、200ms 以上途切れたら書きかけの行を捨てる

### 6.3 USB の診断パネル（`u`）

一覧の領域に 7 行で表示し、0.5 秒ごとに更新する。`S` は媒体関連の失敗を ADSC の STALL で返した回数、`enum` は直近のバスリセットから USB の構成完了までの時間。`sense` は `REQUEST SENSE` の Bulk IN と Interrupt IN について、送信待ちの解消を観測した回数と送信登録数を表示する。`RS` は直近 3 件のセンスコードと各 IN の状態を表示する。いずれも送信状態は OTG レジスタを読み取って観測し、履歴は USB バスリセット後も残る。開発用 CDC の `stats` では、サスペンド、DIEPINT の生値、コマンド間隔も表示する。各行の形式は `app::usb_stats_lines` のコメントを参照。

- 緑: 本体が SD を読み書きしている（一覧、挿入、設定の保存、空イメージの作成）
- 橙: USB からの読み書き（最後のアクセスから 80ms で消える）

## 7. 音

### 7.1 出力（`board::v1::audio`）

- I2S0（TDM Philips）、16kHz、16bit ステレオ（左右に同じ値）。DMA のストリームバッファ 16KB（約 256ms）
- 空きができるたびに 128 フレームずつ合成して詰める
- 補充が間に合わずに転送が止まったら、バッファを作り直して無音から再開する（回数は `UNDERRUNS`）

### 7.2 合成（`sound::synth`）

録音は使わず、インパルスとノイズを 2 次の共振器に通して作る。調整用の定数はファイルの先頭にある。

| 音 | 作り方 |
|----|--------|
| ステップ音 | 450Hz の短い響きと 100Hz の胴鳴りを重ねる。ヘッドの目標シリンダまで 3ms 間隔で 1 ステップずつ鳴らし、着いたら 15ms 休む（1 回に最大 84 ステップ） |
| ディスクがこすれる音 | 180Hz 付近に絞ったノイズをごく小さく。1 回転（5Hz）ごとに強弱。最後のアクセスから 2 秒で止まる（立ち上がり約 0.2 秒、止まるのに約 0.4 秒） |
| 挿入 / 取り出し | 電子音。挿入は 1047Hz → 1568Hz、取り出しは逆。各 60ms の三角波 |

音量ごとの振幅（i16 のフルスケールに対する倍率）は 0 / 2500 / 6000 / 14000。

### 7.3 実機速度モード（`usb::transfer::mechanics`）

オンのとき、セクタを読み書きする前に次の時間だけ待つ。

- 1 回転（200ms）÷ 1 トラックのセクタ数（1.44M なら約 11ms）
- シリンダが変わったら 3ms × トラック数 + 静定 15ms
- 最後のアクセスから 2 秒以上たっていたら、モーターの立ち上がり 300ms

300KB の読み出しが 0.7 秒 → 7.5 秒（約 40KB/s）になる。

## 8. 設定ファイル（`CARDFDD.CFG`）

SD のルートに置く。`key=value`、`#` から行末はコメント、知らないキーは無視する。ファイルがなければ既定値で動き、挿入・取り出し・書き込み禁止・音量・実機速度モードの変更のたびに保存する（書き直す）。

| キー | 既定値 | 内容 |
|------|--------|------|
| `image_dir` | `/FLOPPY` | イメージを置くフォルダ（見つからなければルート） |
| `last_image` | （空） | 前回のイメージのパス（自動で書き換わる。取り出すと空になる。形式は下記） |
| `auto_mount` | `1` | 起動時に前回のイメージを挿入する |
| `write_protect` | `0` | 書き込み禁止スイッチ |
| `volume` | `2` | 音量（0 = 消音 .. 3） |
| `speed_emulation` | `0` | 実機速度モード |
| `usb_mode` | `ufi-cbi` | `ufi-cbi` / `ufi-bot` / `scsi`（再起動後に反映） |
| `usb_vid` / `usb_pid` | `0x1209` / `0x0001` | VID/PID（再起動後に反映） |
| `usb_manufacturer` / `usb_product` | `card-fdd` / `USB Floppy` | 製造者名・製品名（再起動後に反映） |

USB の項目の既定値は、ビルド時の環境変数 `CARDFDD_USB_MODE` / `CARDFDD_USB_VID` / `CARDFDD_USB_PID` でも変えられる（設定ファイルにあればそちらが優先）。

ファイルは行ごとに UTF-8 として読む。UTF-8 として読めない行（別の文字コードで保存し直した行など）はその行だけ無視する。ファイルが読み込みバッファ（`config::MAX_LEN`）より大きいときは、途中で切れた最後の行を無視する。

`last_image` の形式:

- 本体が書くのは `v1:` で始まる形式。ルートからの各フォルダ名とファイル名を `/` でつなぐ。名前は LFN（なければ 8.3 名）をそのまま UTF-8 で書き、スペース・`#`・`%`・ASCII の制御文字だけを `%XX`（16 進 2 桁）にする。例: `v1:/FLOPPY/My%20Games/ゲーム.img`
- 読むときは各要素を大文字小文字を区別せず（ASCII のみ）元の名前と照合する。同じ名前に一致する項目が複数あれば見つからない扱いにする。一覧の表示上限（128 件）を超えた位置のファイルも探す
- `v1:` で始まらない値は以前の形式（表示名をつないだパス。例: `/FLOPPY/GAMES/disk1.img`）として読む。表示名または 8.3 名で照合する。次に挿入したときに `v1:` 形式で保存し直す
- 長さの上限は、8 階層のフォルダとファイル名がそれぞれ 255 文字の LFN でも収まる値（`config::MAX_IMAGE_PATH`）

## 9. ビルドと書き込み

### 9.1 準備

- espup の esp ツールチェーン（Xtensa 用 Rust 1.95）と espflash 4.5
- Xtensa のリンカに PATH を通す: `source ~/export-esp.sh`
- `tools/` のスクリプトに Python 3 と pyserial

### 9.2 ビルドの種類

| 用途 | コマンド | USB の構成 |
|------|---------|-----------|
| 普段使い・Windows | `cargo run --release` | マスストレージのみ |
| 開発用（Linux） | `cargo run --release --features dev-cdc` | マスストレージ + CDC-ACM |

Windows でフロッピーとして使うときは、CDC なし（既定）でビルドする。`CARDFDD.CFG` で `usb_mode=ufi-cbi` を指定し、`usb_vid` / `usb_pid` を既知の USB フロッピーの値（例 `0x0644` / `0x0000`）に設定してから本体を再起動する。

### 9.3 書き込みの流れ（`tools/flash.sh`、cargo run のランナー）

1. 書き込み先を探す。USB-Serial-JTAG（ROM のダウンロードモード）があればそれを使う
2. なければ開発用 CDC に `download` を送ってダウンロードモードにする（3 回まで送り直す）。CDC もなければ、本体で Ctrl+Alt+D を押すのを 60 秒待つ
3. `espflash flash --after no-reset` で書き込む
4. `clear-download-boot.py` で FORCE_DOWNLOAD_BOOT を消し、RTC ウォッチドッグでリセットする
5. CDC が現れたら `monitor.py` でログを表示する（`NO_MONITOR=1` で省略）

シリアルポートを開くときは、DTR を立てたまま開いてから下げる（USB-Serial-JTAG は「RTS=1, DTR=0」をリセットと見なすため）。

### 9.4 ログ

- 出力先: Grove の UART1（G2、115200bps、常時）、USB-Serial-JTAG（USB を OTG に切り替えるまで）、開発用 CDC（切り替え後）
- レベルは `.cargo/esp-config.toml` の `ESP_LOG`（既定 info）
- 起動直後のログは `tools/monitor.py`（RTS でリセットしてそのまま読む）で読む

## 11. 既知の課題と制約

- 開発用 CDC 付きのビルドに Windows 用の VID/PID を設定すると、Windows では開始に失敗する
- 書き込み中に電源が切れたときの動作、使用中の SD の抜き差し、断片化したイメージファイル、非 ASCII のファイル名は未確認（PLAN.md 9 章）
- サスペンド中の消費電流の規定、申告した消費電流（100mA）は守れていない可能性がある
- 既定の VID/PID（pid.codes のテスト用）は配布には使えない
- 音色は調整を保留中

# 電池残量表示 改善計画書

電池残量の表示が、電池だけで動かしているときと USB につないでいるときで当てにならない問題を扱う。
現行の実装は [DESIGN.md](DESIGN.md) 2 章（ハードウェア）と 3.2 節（メインタスクの電池電圧の読み取り）を参照。

- ステータス（2026-11-25）: 計画のみ。実装なし
- 対象: Cardputer v1.1 と Cardputer-Adv（[ADV_PLAN.md](ADV_PLAN.md)）

---

## 1. 現象

- Adv で、電池残量の表示が数秒ごとに増えたり減ったりする（2026-11-25）
- 電池だけで動かしているときと USB につないでいるときで、読み出す値が違うように見える

### 1.1 試して戻したこと

読み取りを 1 秒ごとにして平均し、表示を変える幅を 1% にする変更を入れたが、元に戻した（2026-11-25）。
原因が ADC のノイズではなく電源のつながり方（2 章）にあると考えられ、平均しても USB 接続中の偏りは消えないため。

---

## 2. 原因の見込み（回路図から）

Adv の回路図 v1.0（2025-06-20）の 1 ページ目から読み取った電源まわり:

```
 USB 5V ─┬─ D1 ──────────────────────────────┬─ VBAT_OUT ─→ 昇圧（5V）/ 3.3V レギュレータ
         │                                   │
         └─ TP4057（充電 IC）BAT ─┬─ VBAT_IN ─┴─ Q1（USB 5V があると OFF。CN809J が制御）
                                  │
                                  ├─ R8 100k ─┬─ R12 100k ─ GND
                                  │           └─ G10（ADC）
                                  │
                                  └─ Q3 ─ Q2 ─ 電池（Q2 / Q3 は電源スイッチ SW1 で ON / OFF）
```

- **G10 が測っているのは電池そのものではなく VBAT_IN**（充電 IC の出力の節点）。電池は電源スイッチ（SW1）が ON のときだけ、Q2 / Q3 を通して VBAT_IN につながる
- USB の 5V があると Q1 が切れ、本体は D1 を通して USB から給電される。電池は充電されるだけになる
- 充電 IC の状態ピン（CHRG / STDBY）と USB の VBUS は GPIO につながっていない（v1.1 と同じ。PLAN.md 8.1 節）

ここから、状態ごとに G10 の値は次のようになると考えられる。

| # | USB | 電源スイッチ | G10 に見える電圧 | 表示への影響 |
|---|-----|-------------|-----------------|-------------|
| S1 | なし | ON | 電池の電圧（負荷で少し下がる） | ほぼ正しい |
| S2 | あり | ON、充電中 | 充電 IC の出力（電池の電圧より高い。定電圧の段階では約 4.2V） | 実際より多く表示される。満充電前に 100% になる |
| S3 | あり | ON、充電完了 | 電池の電圧（充電が止まった直後は高め、その後ゆっくり下がり、再充電の電圧で充電が再開する） | 少しずつ下がって戻るのを繰り返す |
| S4 | あり | **OFF** | **電池がつながっていない充電 IC の出力**。電池なしの TP4057 は出力が上下を繰り返すことが多い | **値に意味がない。数秒周期で増減する可能性が高い** |

報告された「数秒ごとに増えたり減ったりする」は S4（USB 接続中に電源スイッチが OFF）か S3 の可能性が高い。どちらなのかは 4 章の測定で確かめる。

v1.1 の電源まわりも TP4057 と 100k + 100k の分圧で同じ構成と見ているが、分圧がスイッチのどちら側にあるかは回路図で確かめていない（3.1 節）。

---

## 3. 確かめること

### 3.1 回路図

- [ ] v1.1 の回路図（PLAN.md 8.1 節のリンク）で、G10 の分圧がどの節点（電池側か、充電 IC の出力側か）につながっているか
- [ ] Adv の Q1 / CN809J の読み取りが正しいか（USB 5V があると電池からの給電が切れるか）

### 3.2 実機での測定

測るのは電圧（mV）。今は画面に % しか出ないので、測定用に電圧を出す手段を作る（5 章 B0）。

| 状態 | 測ること |
|------|---------|
| S1 電池のみ、スイッチ ON | 電圧と、SD アクセス・音を鳴らしたときの下がり幅 |
| S2 USB（PC）、スイッチ ON、充電中 | 電圧、時間とともにどう変わるか |
| S3 USB、スイッチ ON、充電完了 | 電圧の変化の周期と幅 |
| S4 USB、スイッチ OFF | 電圧の変化の周期と幅 |
| S2〜S4 を USB 充電器（データ通信なし）で | PC と違いがあるか |
| S1 ↔ S2 の切り替え | USB を抜き差しした直後に電圧がどれだけ跳ぶか |

両機種で測る。1 秒ごとに数分間記録する。

---

## 4. 方針の候補

ハードウェアの制約上、「USB につながっているか」「充電中か」を直接知る方法はない。手がかりは次の 2 つ。

- **USB の状態**: PC とつながっていれば embassy-usb の状態（構成済み / サスペンド）でわかる。USB 充電器（データ通信なし）では判別できない
- **電圧そのもの**: 4.15V を超える、短い周期で大きく揺れる、USB を挿した瞬間に跳ぶ、などの特徴

候補（測定の結果を見て選ぶ）:

| 案 | 内容 | 長所 | 短所 |
|----|------|------|------|
| A | USB の状態が「PC」「サスペンド」の間は % を出さず、`USB` などと表示する | 簡単。PC 接続中の誤った表示がなくなる | USB 充電器では効かない |
| B | 電圧の特徴（4.15V 超、揺れの大きさ）から外部電源とみなし、% の代わりに `CHG` / `EXT` などを出す | 充電器でも効く可能性がある | 閾値を測定で決める必要がある。誤判定の恐れ |
| C | 電池だけのとき（S1 と判定できたとき）の最後の値を覚えておき、外部電源の間はそれを薄い色で出す | 残量の目安が消えない | 充電で増えた分は反映されない |
| D | 平均化と表示のヒステリシス（1.1 節で試したもの） | S1 のノイズや負荷での下がりを抑えられる | S2〜S4 の偏りは直らない。A〜C と組み合わせる前提 |
| E | 電圧から % への換算を、直線ではなくリチウムイオン電池の放電曲線の表にする | S1 の % がより実態に近くなる | 電池ごとの差がある。別の改善として扱う |

今の見込みでは **A + B で外部電源の間は % を出さず、S1 では D で落ち着かせる** 組み合わせが有力。E は余裕があれば行う。

## 5. 開発フェーズ

| Phase | 内容 | 完了条件 |
|-------|------|---------|
| **B0. 測定の手段** | 電池電圧を mV で出す。開発用 CDC のコマンド（例 `bat`）か、debug レベルで 1 秒ごとにログに出す。USB の状態も一緒に出す | ログから 3.2 節の表を埋められる |
| **B1. 測定** | 3.1 節の回路図の確認と、3.2 節の測定を両機種で行い、この文書に結果を書く | 各状態の電圧の範囲・揺れ方がわかり、原因が確定する |
| **B2. 方針の決定** | 4 章の案から選び、閾値（B を選んだ場合）を決める | 表示の仕様が決まる（画面の文字列を含む） |
| **B3. 実装** | 選んだ案を実装する。判定はハードウェアに依存しない関数にまとめる（ホストでのテストが整ったらテストを書く。PLAN.md 9.1 節） | S1〜S4 のそれぞれで、表示が仕様どおりになる |
| **B4. 文書** | DESIGN.md の電池の説明と、画面の説明（6.1 節）を更新する | |

## 6. 決めること

| # | 項目 | 案 |
|---|------|----|
| E1 | 外部電源の間の表示 | `USB` / `CHG` / `EXT` / 最後の値を薄く表示、のどれにするか（B2 で決める） |

## 7. リスク

| リスク | 影響 | 対策 |
|--------|------|------|
| 回路図の読み違い | 原因の見込みが外れる | B1 の測定で確かめてから方針を決める |
| 電圧の特徴による判定の閾値が電池の状態や個体で変わる | 誤判定 | 余裕を持った閾値にし、USB の状態（案 A）と組み合わせる |
| v1.1 と Adv で電源まわりが違う | 片方だけ直らない | 両機種で測る。必要なら判定を機種ごとに分ける（`board::model()`） |

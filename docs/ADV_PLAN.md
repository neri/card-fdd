# Cardputer-Adv 対応 計画書

card-fdd を **M5Stack Cardputer-Adv** でも動かすための計画。
現行の要件・設計は [PLAN.md](PLAN.md) と [DESIGN.md](DESIGN.md) を前提とし、この文書は Adv 対応で変わる部分だけを扱う。

- ステータス（2026-11-25）: ブランチ `adv-support` で A1 と、A3 / A4 のコードまで実装した。v1.1 と Adv の両方の実機で、画面表示、SD の操作、全キー、音と音量、USB での読み書き、LED、ダウンロードモードを確認した。未確認は電池残量だけ（[BATTERY_PLAN.md](BATTERY_PLAN.md)）。詳細は 10 章
- 対応方針（案）: **1 つのファームで v1.1 と Adv の両方を動かす**。起動時に機種を判別する（2 章、8 章 D1）
- 対応範囲: v1.1 でできることを Adv でもできるようにする。Adv だけにある機能（IMU、マイク、IR、EXT ヘッダ）は使わない

## 1. v1.1 との違い

情報源: [公式ドキュメント](https://docs.m5stack.com/en/core/Cardputer-Adv)、[回路図 v1.0（2025-06-20）](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1178/Sch_M5CardputerAdv_v1.0_2025_06_20_17_19_58.pdf)。2026-11-24 に確認した。

| 機能 | v1.1 | Adv | card-fdd への影響 |
|------|------|-----|------------------|
| MCU | Stamp-S3A（ESP32-S3FN8） | 同じ | なし |
| USB | G19 / G20 | 同じ（同じモジュール） | なし |
| 液晶 | ST7789V2、G33〜G38 | 同じピン（公式のピン表） | なし（実機で確認） |
| MicroSD | SPI: G40 / G39 / G14 / CS G12 | 同じ（回路図） | なし |
| RGB LED | G21、電源は G38 と共通 | G38 が LED の電源スイッチ（PWR_EN）を兼ねる | 今と同じく G38 を High のままにする（実機で確認） |
| 電池電圧 | G10、100k + 100k の分圧 | 同じ（回路図 R8 / R12） | なし。`AdcBattery` をそのまま使える |
| 充電 IC | TP4057、状態ピンは GPIO 未接続 | 同じ | なし |
| Grove | G1 / G2 | 同じ | なし（G2 の UART ログはそのまま） |
| **キーボード** | 74HC138 + 7 列のマトリクス（G8, G9, G11 / G13, G15, G3〜G7） | **TCA8418（I2C 0x34）**。SDA G8、SCL G9、INT G11。ROW0〜6 × COL0〜7 の 56 キー | **ドライバを新規に書く**（4 章） |
| **音** | NS4168（I2S アンプ。初期設定なし） | **ES8311 コーデック（I2C 0x18）** + NS4150B アンプ。I2S は SCLK G41、LRCK G43、DSDIN G42（再生）、ASDOUT G46（録音）。**MCLK は未接続** | **コーデックの初期設定を追加する**（5 章） |
| アンプの有効化 | 常に有効 | NS4150B の CTRL は 10kΩ で 3.3V に吊られ、ヘッドホンを挿すと回路で Low になる | GPIO 操作は不要 |
| 3.5mm ジャック | なし | あり（挿すとスピーカーが止まる） | ヘッドホンでの音量を確認する |
| IMU | なし | BMI270（I2C 0x69） | 使わない |
| EXT 14 ピン | なし | G3〜G6、G13、G15、G8 / G9、G40 / G39 / G14 | 使わない。**v1.1 のキーボード用ピンが空く** |
| 電池容量 | 120mAh + 1400mAh | 1500mAh（2026-07 から。以前は 1750mAh） | なし |

I2C アドレスは回路図の記載（TCA8418「7-bit Address 34H」、BMI270「69H」）と、ES8311 の CE ピンが GND につながっていることからの推定（0x18）。ES8311 は実機で確認する。

ピンの使い方が変わるのは **G3〜G9、G11、G13、G15（キーボード）と G46（Adv では録音データ）** だけ。G41 / G42 / G43 は役割が同じで、相手の IC が変わる。

## 2. 機種の判別

### 2.1 方法（案）

起動直後、キーボードやオーディオを初期化する前に、G8（SDA）/ G9（SCL）で I2C を立ち上げ、**0x34（TCA8418）が ACK を返すか**を見る。

- ACK あり → Adv
- ACK なし → v1.1

v1.1 では G8 / G9 は 74HC138 のアドレス入力につながっているだけなので、I2C の波形を出しても害はない（キーの読み取りが一瞬乱れるだけで、まだスキャンしていない）。

### 2.2 注意点

- **G11 の扱い**: v1.1 では 74HC138 のアドレス出力、Adv では TCA8418 の INT（オープンドレイン出力）。Adv で v1 のドライバを動かすと、G11 の High 出力と INT の Low がぶつかる。**判別が終わるまで G11 を出力にしない**
- 誤判別を減らす: 判別の前に SCL を 9 回送ってバスを解放し、0x34 への問い合わせを数回やり直す。TCA8418 のレジスタ（例えば `CFG`）を読めるかも確かめる
- 判別を強制する手段として cargo feature `board-v1` / `board-adv` を用意する（どちらも付けなければ自動）。設定ファイルでの指定は、SD を読むのがキーボードの初期化より後なので採らない
- 判別結果はログと情報表示（ステータス画面の一角、または `i`）に出す

## 3. ボード層の整理

### 3.1 方針

`Keyboard` trait は `async fn` を持つので `dyn` にできない。機種ごとの実装を **enum でまとめて静的にディスパッチ**する。

```rust
pub enum Model { V1, Adv }

pub enum AnyKeyboard { V1(v1::MatrixKeyboard), Adv(adv::Tca8418Keyboard) }
impl Keyboard for AnyKeyboard { /* match で振り分け */ }
```

音は `board::v1::audio::run` のうち I2S + DMA の部分が両機種で共通なので、共通部分を `board::audio` に移し、Adv ではその前にコーデックを初期化するだけにする。

### 3.2 変更するファイル

| ファイル | 変更 |
|---------|------|
| `src/board/mod.rs` | `Model`、`detect()`（バスの解放と 0x34 の問い合わせ）、`AnyKeyboard`。モジュールのコメントのピン表を機種別にする |
| `src/board/adv/mod.rs`（新規） | Adv 固有の実装。G8 / G9 の I2C（400kHz）の初期化 |
| `src/board/adv/keyboard.rs`（新規） | TCA8418 のドライバ（4 章） |
| `src/board/adv/codec.rs`（新規） | ES8311 の初期設定（5 章） |
| `src/board/audio.rs`（新規） | `v1/audio.rs` の I2S + DMA 部分を移す。`UNDERRUNS` もここへ |
| `src/board/battery.rs`（移動） | `v1/battery.rs` を移す（Adv も同じ分圧） |
| `src/bin/main.rs` | 判別 → 機種に応じたキーボードとオーディオの初期化。`keyboard_task` の引数を `AnyKeyboard` にする |
| `src/app.rs` | `board::v1::audio::UNDERRUNS` の参照先を変える（959 行付近）。情報表示に機種名を出す |
| `Cargo.toml` | feature `board-v1` / `board-adv`（強制用）。新しい依存クレートは追加しない（I2C は esp-hal のものを使う） |

`config.rs` の `last_image` の `v1:` は設定の書式の版で、ボードの v1 とは関係ない。名前が紛らわしいので、コードのコメントで区別しておく。

## 4. キーボード（TCA8418）

### 4.1 初期化

TCA8418 のデータシートで値を確認してから実装する。予定している設定:

- `KP_GPIO1`（0x1D）= 0x7F: ROW0〜6 をキーパッドに使う
- `KP_GPIO2`（0x1E）= 0xFF: COL0〜7 をキーパッドに使う
- `KP_GPIO3`（0x1F）= 0x00: COL8 / COL9 は使わない
- `CFG`（0x01）: キーイベントの割り込み（KE_IEN）と FIFO あふれの割り込みを有効にする
- 起動時に FIFO を読み切り、`INT_STAT`（0x02）を消す

### 4.2 イベントの読み取り

- G11（INT、Low アクティブ。基板上で 3.3kΩ で吊り上げてある）の立ち下がりを `Input::wait_for_falling_edge` で待つ。取りこぼし対策に、100ms 程度のタイムアウトでも FIFO を見に行く
- `KEY_LCK_EC`（0x03）でイベント数を読み、`KEY_EVENT_A`（0x04）を数だけ読む。bit7 が押下（1）/ 解放（0）、下位 7 ビットがキー番号（`row * 10 + col + 1`）
- 読んだイベントで押下状態のビットマップ（v1 と同じ `u64`、`KeyPos::index()` の並び）を更新し、v1 と同じく `input::modifiers_from_bitmap` と `input::resolve` で `KeyEvent` を作る。**チャタリング除去は TCA8418 に任せる**
- FIFO があふれたら、全キーの解放として扱ってビットマップを消す（修飾キーが押しっぱなしにならないように）

### 4.3 キー番号 → 物理位置（4×14）

回路図では、ROW0〜6 がそれぞれ物理的な 2 列を、COL0〜7（Y0〜Y7）が物理的な行を受け持つように見える。ただし対応は回路図から読み切れないので、次の順で決める。

1. M5Stack 公式ライブラリ（M5Cardputer）の Adv 用キーボードの実装で対応表を確認する
2. 実機で、生のキー番号を画面に出す開発用の表示（`u` の診断パネルと同じ要領）を作り、56 キーすべてを押して確かめる
3. 対応表は `input.rs` の `KeyPos` に変換する純粋な関数にし、ホストでのテスト（PLAN.md 9.1 節）が整ったらテストを書く

キートップの刻印と配列は v1.1 と同じ前提で、`input.rs` の `BASE` などの表は変えない（実機で確認する）。

## 5. 音（ES8311）

### 5.1 クロック

- **MCLK が配線されていない**ので、ES8311 のクロック源を SCLK（BCLK）にする（レジスタ 0x01 の MCLK 選択）
- 今の I2S は 16kHz・16bit ステレオで、BCLK = 32fs = 512kHz。ES8311 の内部の逓倍（MULT_PRE など）でこの比率が扱えるかをデータシートと Espressif の ES8311 ドライバ（esp-bsp / esp-adf、参考にするだけで依存はしない）で確認する
- 扱えなければ、スロットを 32bit にして BCLK を 64fs にする（`DataFormat::Data32Channel16` など）か、サンプリング周波数を上げる。合成側（`sound::SAMPLE_RATE`）は定数を変えれば追従する

### 5.2 初期化の順番

1. I2S の DMA を無音で始めて、BCLK / LRCK を出す
2. ES8311 をリセットし、クロック（SCLK 由来、16kHz）、I2S スレーブ・16bit、DAC の電源、出力（OUTP / OUTN）を設定する
3. DAC の音量（レジスタ 0x32）は固定にする

I2C は G8 / G9 をキーボードと共有する。初期化は起動時に 1 回だけなので、**コーデックを設定し終えてから I2C をキーボードのドライバに渡す**。実行中にコーデックへアクセスしない。

### 5.3 音量

- 音量（0〜3）は今と同じく合成側の振幅で変える（`sound::synth` の 0 / 2500 / 6000 / 14000）。コーデックの音量は I2C の共有が必要になるので使わない（8 章 D2）
- NS4150B と 1W スピーカー、ヘッドホンでは聞こえ方が変わるので、実機で振幅の表を調整する。機種ごとに表を分けるかはそのときに決める
- 録音（ASDOUT、G46）は使わない。ADC は電源を落としておく

## 9. リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| ES8311 が BCLK = 32fs のクロックで動かない | 音が出ない、ひずむ | 64fs やサンプリング周波数の変更を試す（5.1 節）。最悪の場合、Adv では音なしで出す |
| キー番号と物理位置の対応を間違える | キー操作が効かない | 公式ライブラリと実機の生表示の両方で確かめる（4.3 節） |
| 判別を誤り、Adv で v1 のドライバが動く | G11 で出力がぶつかる、キーが効かない | バスの解放とやり直し、レジスタの読み出しで確かめる。feature で強制できるようにする |
| G38 が LED の電源とバックライトを兼ねる仕様の違い | LED が光らない | 今の実装（G38 を常に High）のまま確認する。違えば Adv のときだけ扱いを変える |
| ヘッドホンで音が大きすぎる | 耳への負担 | 既定の音量の振幅を実機で確かめ、必要なら Adv では振幅を下げる |
| Adv の実機が手元にない間は検証できない | A2 以降が進まない | A1（v1.1 での回帰確認まで）を先に終えておく |
| 回路図の版が変わる（電池容量はすでに変更あり） | ピンやアドレスが変わる可能性 | 回路図の版と確認日をこの文書に残す。判別とアドレスは実機で確かめる |

## 10. 実装の状況（2026-11-25、ブランチ `adv-support`）

実機なしで進められるところまで実装した。`cargo build --release` と、feature なし / `dev-cdc` / `board-v1` / `board-adv` での `cargo clippy --release` が警告なしで通る。`board-v1` と `board-adv` を両方付けるとビルドエラーにした。

### 10.1 実装したこと

- **ボード層の整理（A1）**: `board::audio`（I2S + DMA）と `board::battery` を `v1` から共通に移した。`v1` に残るのはキーボードだけ
- **機種の判別**: `board::detect` が SCL を 9 回送ってバスを解放してから、100kHz の I2C で 0x34 の `CFG` を最大 3 回読む。読めれば Adv。結果は `board::model()` で参照でき、起動ログと開発用 CDC の `cfg` に出る。G11 には判別前は触れない
- **キーボード（A3 のコード）**: `board::adv::Tca8418Keyboard`。初期化（4.1 節）、INT の Low 待ち（100ms ごとにも FIFO を確認）、FIFO の読み出し、押下状態のビットマップの更新、FIFO あふれ時の全キー解放。キー番号から物理位置への変換は公式ライブラリの `remap` と同じ式（物理行 = COL % 4、物理列 = 2 × ROW + (COL ≥ 4)）で、`decode_event` にまとめた。生のイベントは debug レベルでログに出る
- **音（A4 のコード）**: `board::adv::codec::init`。M5Unified が Cardputer-Adv のスピーカーを有効にするときと同じ 8 つのレジスタを書く。MCLK は BCLK から取り、逓倍は ×8。16bit ステレオでは BCLK = 32fs なので 256fs になり、今の 16kHz のままで済む見込み（5.1 節のリスクはほぼ解消）。チップ ID（0xFD / 0xFE）はログに出すだけ
- 初期化の順番（Adv）: 判別 → I2C（400kHz）→ ES8311 の設定 → I2C をキーボードに渡す → 音のタスクを起動。I2S を始める前にコーデックを設定している

### 10.2 実機で確かめること

- [x] v1.1 で v1 と判別され、キーと音が今までと同じ（判別で G8 / G9 に I2C を流しても問題がない）（2026-11-25、主なキー操作と音で確認）
- [x] Adv で Adv と判別される。ES8311 のチップ ID が 83 11（2026-11-25、開発用 CDC のログで確認）
